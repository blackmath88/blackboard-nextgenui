# CLI Pilot v1: concept and build plan

> One terminal. Not really a terminal.
> A chat that grows into a workbench as the project grows.

This folder is the planning package for the first real build. Nothing here is code yet.

| File | What it answers |
|---|---|
| `01-concept.md` | What the pilot is, what it is not, and what a week with it feels like |
| `02-architecture.md` | Files as blackboard, server, controller, model roles, the page |
| `03-prior-art.md` | Bits and pieces found on GitHub: what to reuse, borrow, or avoid |
| `04-build-plan.md` | Six small, reversible steps with acceptance checks |
| `05-decisions.md` | The decisions taken, ADR style, each with what would reverse it |
| `06-open-questions.md` | What stays open on purpose |
| `schemas/` | Example config, rules, and JSON Schemas for state, modules, extraction |
| `brief/claude-code-brief.md` | A self-contained brief to hand to Claude Code or Orca |

Lineage: the four explainers (blackboard, morph, Rolle und Kodex, growing workbench) and the two conversation summaries. The pilot is the first thing that has to work on real work, not in a simulation.
