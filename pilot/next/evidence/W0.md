- npm scripts: `start` → `node server.js`; `demo` → `node scripts/demo.js <version>`; `verify` → `bash scripts/verify-all.sh`; `stats` → `node scripts/stats.js [dir]`. There is no package bin or init/doctor CLI. No dependencies or install/build step.
- `PILOT_CONFIG` resolves relative to pilot/app (absolute paths accepted), default pilot.config.json. `PILOT_DIR` overrides config.pilotDir, then defaults to `.pilot`; it resolves relative to pilot/app. Contrary to the initial inventory assumption, server.js:54 rejects directories outside pilot/app, including absolute OS temp paths. W0 therefore creates fresh `mkdtemp` roots **inside pilot/app**, named `.pilot-verify-run-*`, with `.pilot-fixture` ownership markers; no server change is necessary.
- `PILOT_DEMO_DIR` defaults to `.pilot-demo` and accepts `.pilot-demo*` names. Existing marked demo fixtures can be reseeded; existing unmarked directories are now refused. Verification passes an absolute `.pilot-demo*` path inside its fresh root with internal `PILOT_FIXTURE_ROOT`; ordinary demo usage retains its named directory and printed commands. `DEMO_PORT_SHIFT` shifts every demo server/fake port. Unknown versions exit 2 and list available versions. `try.sh <tag>` creates a detached temporary worktree, runs that tag's demo, and removes its owned worktree/root; `TRY_REF` overrides the checkout ref.
- Stats accepts a directory relative to `INIT_CWD`/cwd, defaults to pilot/app/.pilot, and is read-only. Browser runner supports p1/p2, v03–v10, or all (= p1/p2); `CHROME` overrides its macOS Chrome default. SHOT/SHOT_DIR opt into screenshot output. Verification uses fake models only, never real endpoints or keys.
- Tests: dev/verify-p0,p1,p2; verify-v0.3 through v0.10; browser-check.js (CDP via global WebSocket); fake-model.js; contrast-check.js; sse-probe.js; why-cites.js; make-fixture-v06/v08/v09/v10.js. New verify-w0-safety.sh is picked up by verify-all's existing glob. `verify-all` determines verdicts from FAIL lines and ALL…PASSED markers (P0: assistant transcript plus exit status), then prints the existing summary and aggregate exit code; P1/P2 historically return zero even for failed assertions.

## Hazards and fixes

1. P0–P2 deleted the real `.pilot` and used its real default HTTP port. Each now exports PILOT_DIR into a fresh marked fixture root and generates a 4750 dev config, including alternate timeout/manual configs. File reads/edits use that fixture path; P2 resets only its marked data fixture.
2. Versioned checks reused fixed app-local verification/demo directories and unquoted deletes. All data, auxiliary fixture copies, logs, and demo paths now live beneath a fresh root; shell file paths are quoted. Reset operations create ownership markers after guarded removal.
3. verify-all relied on `.pilot` being absent initially, then deleted it on EXIT. Both the precondition and deletion are gone; only its own marked output root is cleaned. Summary/verdict semantics remain unchanged.
4. `dev/lib/safe-dir.js`, with a shell wrapper, centralizes destructive fixture deletion. It refuses empty/unset paths, `/`, HOME, any `.pilot` basename, symlinks or symlinked ancestors escaping the canonical path, and existing directories without a regular ownership marker. Only marked directories inside the run root, or marked known `.pilot-demo*`/`.pilot-verify*` throwaway names, may be deleted. A nonexistent eligible fixture is a no-op; marker creation occurs only after refusal checks, never to legitimize existing user data.
5. Demo reseeding and browser fixture/profile cleanup use the guard. Browser P1/P2 use isolated marked data and generated 4750 configs; per-scenario config/profile directories are below the run root and removed after children stop. try.sh keeps its temporary worktree below its owned marked root, marks and validates that worktree before Git removal, and guards final root removal.
6. New self-test creates its own real-directory sentinel and an unmarked demo sentinel, exercises dangerous inputs and occupied-port refusal, runs P0/P1/P2 and actual demo reseeding/cleanup, and compares sentinel bytes. Its finally block unlinks only its exclusively created sentinel files and removes only empty directories it created; it never recursively deletes `.pilot` or the unmarked demo.

## Limitations

- This is test/demo isolation, not a sandbox for hostile concurrent filesystem modification. Port preflight detects occupied ports but does not reserve them atomically until children bind; fixed test ports intentionally make competing verification runs fail rather than share a service.
- Fixture temp roots stay below pilot/app because of the existing server restriction. They are fresh, private, marked directories, not configurable user data locations. Abrupt SIGKILL can leave owned fixtures behind; the guard still refuses unmarked directories.
- Normal demos keep their named marked data directory after stopping, preserving existing inspection/restart usage. They refuse an existing unmarked directory instead of adopting it. Old tags run by try.sh retain their own historical demo implementation inside a disposable worktree.
- Full verification still exits 1 on this Linux machine for the documented pre-existing browser-default/GNU sed issues. No browser-default, GNU sed, watcher timing, server, UI, model, or feature changes were made. Real-model behaviour remains untested.

Additional targeted checks: P0 was run with a test listener occupying 4750; it exited nonzero with `REFUSE port 4750: already in use; stop the other process or choose isolated ports`. `TRY_REF=HEAD bash pilot/app/scripts/try.sh pilot-v9.99` exercised missing-fixture cleanup; its temporary detached worktree and marked root were both removed. try.sh now uses a fixed `pilot` child inside that fresh root, so a supplied tag cannot affect the cleanup path. Bash syntax checks, Node syntax checks, and `git diff --check` pass; `rg -n 'rm -rf' pilot/app/dev pilot/app/scripts` returns no matches, and the only recursive `fs.rmSync` is inside the shared guard.
