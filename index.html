1The problem

Chat became the default interface for working with language models. It is good for curiosity: ask, read, ask again. It is bad for ongoing work. Decisions scroll away, state lives nowhere you can point to, and every reload starts from a blank line.

OpenAI’s Intelligent UI (October 2026) let the model choose the form of its own answers. That raised the question this collection follows:

  • Form. Who decides what an interface looks like?
  • State. Where does its state live?
  • Authority. Who holds authority over it?

2What this is

Four explainers and one build plan, all from a single human–AI conversation between Miro (blackmath88) and Claude. Each piece answers one question and hands the next one on. The explainers run in the browser with no build step. Three of them are in German, one is in English.

4Method

Look back first
Each piece starts with older fields that already solved part of the problem: speech recognition, hypermedia, the book, building and terminal history.
Explain, then simulate
Every explainer is a working model you can step through. It is deterministic, runs offline and is labelled as a simulation.
Evidence labels
Claims say where they come from. In Rolle und Kodex every statement is tagged: an announcement, a third-party analysis, the host app, or our own draft. Simulated model answers are marked as simulated.
End open
No piece pretends to solve its question. Each one ends on the problem it could not close.
Plan in chat, build with agents
The thinking happened in conversation. The build is handed to coding agents as a self-contained brief.

5This repository

This repository is an example of its own subject: a conversation that outgrew chat and had to become a place. The explainers, the plan and this page were written with AI (Claude) and reviewed by a human (Miro). The authorship is stated here, not hidden.

The conversation’s own apparatus is one session summary in JSON: findings, positions taken, prior art and the open questions that started the path.

6Pilot iterations

The CLI Pilot grows in small tagged iterations. Each one runs locally against fake model endpoints in under a minute. To try a tag without touching your checkout: bash pilot/app/scripts/try.sh <tag>.

  • pilot-v0.3 · hardening and pastel palette · cd pilot/app && npm run demo -- v0.3 (or scripts/try.sh pilot-v0.3)
  • pilot-v0.4 · proposals: the model proposes decisions and tasks, you confirm (c) or reject (r); untested with a real model · cd pilot/app && npm run demo -- v0.4 (or scripts/try.sh pilot-v0.4)
  • pilot-v0.5 · live files: hand edits and a second tab show within a second, stale writes are refused; c/r only on a focused proposal · cd pilot/app && npm run demo -- v0.5 (or scripts/try.sh pilot-v0.5)
  • pilot-v0.6 · authorship and metrics: every line, item and pane says who authored it (hand edits read “you (file edit)”); /stats checks the five dogfood measures from metrics.jsonl · cd pilot/app && npm run demo -- v0.6 (or scripts/try.sh pilot-v0.6)
  • pilot-v0.7 · /why: every pane and item explained from the recorded files, each statement with its source (file:line); a “why?” button on panes and cards; narrow layouts keep labels whole · cd pilot/app && npm run demo -- v0.7 (or scripts/try.sh pilot-v0.7)
  • pilot-v0.8 · panes can go: an untouched pane fades to a tab (one click brings it back), and only your answer removes it; never the chat, never a pane holding an open proposal · cd pilot/app && npm run demo -- v0.8 (or scripts/try.sh pilot-v0.8)
  • pilot-v0.9 · Enter, diffused (experiment behind a flag, default off): after a pause on a finished-looking line the input offers “send?” (Tab sends, Enter always sends, nothing goes without a key); offers, accepts and ignores are measured in /stats · cd pilot/app && npm run demo -- v0.9 (or scripts/try.sh pilot-v0.9)
  • pilot-v0.10 · frame proposals (experiment behind a flag, default off): after a turn the model may suggest how the map or kanban arranges its cards, in a closed vocabulary (focus, order, group); it shows as a note “suggested by morrow, not by you”, only f applies it, /frame reset undoes it, /why map explains it · cd pilot/app && npm run demo -- v0.10 (or scripts/try.sh pilot-v0.10)
